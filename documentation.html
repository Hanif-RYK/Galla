Galla POS documentation

Galla POS is a point of sale and inventory admin template for shops, cafés, bakeries, pharmacies and other small retail businesses: a working register screen, sales, returns, customers, products, stock, purchases, suppliers, expenses and reports. It is made with plain HTML, CSS and vanilla JavaScript. There is nothing to install and no build step. Version 1.0.0.

Getting started

  1. Unzip the download and open the Galla folder.
  2. Double-click index.html for the dashboard, or pos.html for the register. Everything works offline.
  3. Open any .html file in a code editor such as VS Code to change text, products, prices and links.

This is the structure of the download. In the download the pages link to these files with paths such as assets/css/style.css, assets/js/app.js and assets/img/favicon.svg, and style.css loads the fonts from ../fonts/.

Live demo: the online demo repository is flattened so it can run on GitHub Pages without folders. All files (the 18 pages, style.css, app.js, pos.js, charts.js, the two .woff2 fonts, logo.svg and favicon.svg) sit in one folder and the paths point to the file names directly. The code is the same; only the paths differ.

The POS screen

  • Add items by tapping a product, typing in the search box, or scanning a barcode. USB and Bluetooth barcode scanners type the code and press Enter; an exact barcode or SKU adds the product straight away.
  • Keyboard: F2, / or Ctrl K focuses the search, Enter adds the scanned or only matching product, F9 opens payment, Esc closes windows and the phone cart sheet. F2 and F9 do nothing while a window such as Payment is open.
  • Cart: change quantities with − and +, type a quantity, or remove a line. The POS will not sell more than the stock shown on the tile.
  • Discount: percent or fixed amount for the whole sale. Tax is worked out after the discount.
  • Hold: park a sale and serve the next customer; resume it from Held.
  • Payment: cash (with quick cash buttons and change), card or mobile wallet. Card and wallet are confirmation screens only; no payment is processed.
  • Receipt: after payment the receipt opens. Print prints only the receipt; in the print window choose your 58 or 80 mm receipt printer, or Save as PDF.
  • Products on the POS are the .ptile buttons in pos.html. Each has data-id, data-name, data-price, data-stock, data-cat, data-sku and data-barcode.
  • On phones the cart becomes a sheet that opens from the View sale bar.

Store, currency and tax

Settings → Store and receipt changes the store name, address, phone, currency symbol, sales tax and receipt footer, with a live receipt preview. Every price marked with data-money, every chart and every receipt follows the chosen currency.

The demo saves these settings in the visitor's browser. The defaults are in the small script in the <head> of each page (window.GALLA); change them there to set your own defaults.

Colours and logo

All colours are CSS variables at the top of assets/css/style.css. Change the four brand variables to rebrand; the first two chart colours follow --primary and --accent. Dark mode has its own versions in the [data-theme="dark"] block just below. The sidebar uses the --side-* variables.

:root {
  --primary: #c23b22;        /* buttons, active menu, charts */
  --primary-strong: #9f2f1a; /* hover */
  --primary-soft: #fbe7e1;   /* light backgrounds */
  --accent: #e6a23c;         /* highlights */
}

The logo is an inline SVG in each page (search for brand-mark) and a file in assets/img/logo.svg.

Fonts

Interface text uses Figtree; prices, receipts and table headings use JetBrains Mono. Both are included as .woff2 files and loaded with @font-face in section 1 of style.css. To use other fonts, change --font-ui, --font-display and --font-mono.

Dark mode

The moon button switches themes and the choice is remembered. On the first visit the template follows the device setting. To start in one theme only, set data-theme on <html> and remove the theme script.

Sidebar menu

The menu is the same block in every page: <nav class="nav">. Add a link with an icon, label and optional .count badge. The current page link has class="active". The sidebar button in the top bar collapses the sidebar on desktop (the choice is remembered); on phones it slides in from the left.

Charts

Charts are SVG, drawn by charts.js from a JSON data-chart attribute. Types: line, area, bar, stacked, donut, spark. They redraw on resize and when the theme changes.

<div class="chart" data-chart='{"type":"bar","prefix":"$","labels":["Mon","Tue"],
  "series":[{"name":"Sales","data":[1650,1420]}]}'></div>

A "$" prefix is replaced by the store currency automatically.

Forms and validation

Add data-validate to a form. Fields with required, type="email", minlength or pattern are checked on submit and the .error-text after the field is shown. Amount fields accept numbers such as 1,250.50. data-success shows a toast and data-redirect opens another page.

All forms are front-end only: nothing is sent to a server. A valid form fires a galla:submit event you can listen to.

Demo data and limits

  • Demo data (products, receipts, customers, suppliers, orders, expenses) is written in the HTML files. Chart numbers are in each data-chart attribute. All names and figures are fictional.
  • Kept in this browser only (localStorage): completed POS sales (last 50), held sales, store settings, the account name and the theme. Clear the site data in the browser to reset them.
  • Not saved after a reload: rows and cards added with forms, stock adjustments and status changes.
  • Needs your backend: real sign-in, sending emails and invites, processing card or wallet payments, importing CSV files, and sharing sales between registers or computers.
  • The demo text on the sign-in page and the store details are placeholders; replace them with your own.

Connecting a backend

  • Sales: in assets/js/pos.js, saveSale(sale) receives the complete sale (number, date, cashier, customer, lines, discount, tax, total, payment method). Send it to your API there.
  • Products on the POS: render the .ptile buttons from your product list (server-side or with JavaScript) before pos.js runs.
  • Forms: listen for galla:submit on a form, or remove data-validate and post the form as usual.
  • Receipts: Galla.receipt(sale) returns the receipt HTML and Galla.printReceipt(html) prints it.

Publishing

Upload the contents of the Galla folder to any web host (cPanel, Netlify, Vercel, GitHub Pages). No server code is needed for the template itself.

Browser support

Latest versions of Chrome, Edge, Firefox and Safari, on desktop, tablet and phone. Printing receipts uses the browser print window.
